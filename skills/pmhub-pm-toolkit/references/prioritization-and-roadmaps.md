# 优先级与路线图

按需用于机会排序、方案选择、版本取舍、资源配置和产品路线图。评分的价值是暴露假设，不是制造客观真相。

## 1. 排序前先对齐比较层级

先确认候选项属于同一层：

- **机会**：用户需要、痛点或期望结果；
- **方案／赌注**：解决机会的路径；
- **需求**：方案必须具备的行为或质量；
- **交付项**：故事、任务、缺陷或技术工作。

不同层级不能直接塞进同一张 RICE 表。先分别排序机会，再比较服务于同一机会的方案；法规、安全和系统稳定性等约束项单独过门槛。

## 2. 选择合适的方法

| 决策场景 | 推荐方法 | 何时不用 |
|---|---|---|
| 少量候选、需要快速讨论 | 结果影响 × 信心 × 工作量，外加硬约束 | 输入差异大、跨战略主题 |
| 同一目标下可估算触达规模的多个方案 | RICE | 无法定义共同时间窗或触达单位 |
| 多战略目标／多团队投资组合 | 加权决策表＋容量边界 | 权重没有决策者背书 |
| 确定发布范围 | Must／Should／Could／Won't for now | 用来决定问题是否值得解决 |
| 高不确定创新 | 最危险假设排序＋信息价值 | 已知的纯执行工作 |
| 客户需求机会 | 重要性、当前满足度、频率、证据可信度 | 只拿内部人的主观评分 |

若用户指定框架，按其框架输出，同时指出失配风险。不要机械叠加五套模型后平均分。

## 3. 通用候选项卡

所有排序方法先补齐这些字段：

```text
Item ID／名称：
层级：机会／方案／需求／交付项
服务的目标：
目标用户与情境：
预期用户结果：
预期业务结果：
证据链接或摘要：
必须满足的约束：
工作量区间与估算人：
依赖：
最危险假设：
可逆性：易／中／难
```

无法连接到目标或用户结果的候选项先进入“待澄清”，而不是靠低分排到底部。

## 4. RICE 的审慎用法

公式：

> RICE = Reach × Impact × Confidence ÷ Effort

- **Reach**：同一明确时间窗内受影响的用户、账户或事件数；所有项必须同单位。
- **Impact**：对共同目标的单体影响。自定义量表时公开刻度含义。
- **Confidence**：对触达和影响估计的证据置信，不是团队热情。
- **Effort**：产品、设计、工程、数据、运营、法务等总投入，注明单位和区间。

输出必须显示原始输入、依据、区间和公式。排名后做一次敏感性检查：若 Reach、Impact 或 Effort 在合理区间变化，前几名是否换位？会换位则视为“近似并列”，下一步是补证据或由战略取舍决定，不假装小数点能拍板。

## 5. 加权决策表

用于比较方向性方案：

1. 决策者确认 3–6 个标准和权重，权重合计 100%。
2. 标准至少覆盖用户价值、战略一致性、业务价值、风险／合规和投入；按情境取舍，不固定全选。
3. 每项采用同一刻度，逐格写证据或假设。
4. 硬门槛先过滤，不能靠其他高分抵消安全或法规阻断。
5. 展示总分、敏感性和定性取舍。

模板：

| 候选项 | 标准 A（权重） | 标准 B | 标准 C | 总分 | 证据置信 | 关键取舍 |
|---|---:|---:|---:|---:|---|---|

## 6. 范围优先级

MoSCoW 只用于一个已决定要做的版本：

- **Must**：缺少就无法实现版本目标、无法合规／安全上线或核心流程断裂；
- **Should**：价值明显，但存在可接受的临时替代；
- **Could**：不影响核心结果，容量允许才做；
- **Won't for now**：本版本明确不做，并记录复查条件。

若 Must 超出容量，不能把所有项继续标 Must；应缩小目标、切纵向薄片、增加真实容量或推迟承诺。

## 7. 结果型路线图

路线图表达“为什么、先解决什么、如何知道有效”，交付计划表达“谁在何时完成什么”。两者关联但不混为一张功能甘特图。

### 选择视图

- **Now／Next／Later**：不确定性高、需要保持方案弹性；
- **季度主题／结果**：需要预算与跨团队协调；
- **带日期的承诺路线图**：合同、法规、活动或依赖确有硬日期时。日期必须标明承诺级别和缓冲，不把探索项伪装成确定交付。

### 每个路线图条目

| 字段 | 内容 |
|---|---|
| Outcome ID | 稳定标识 |
| 目标结果 | 用户／业务行为变化，不是功能名 |
| 目标人群与问题 | 可回链到问题简报 |
| 当前基线与目标 | 无基线则标“待测量” |
| 为什么现在 | 战略、风险、窗口或依赖 |
| 证据与置信 | 研究／数据／约束及局限 |
| 当前赌注 | 方案方向，可随学习调整 |
| 护栏指标 | 防止局部优化伤害整体 |
| 依赖与容量 | 团队、系统、外部方 |
| 时间范围 | Now／Next／Later 或真实窗口 |
| 负责人 | 对结果负责的角色 |
| 复查触发器 | 日期、新证据、指标或风险阈值 |

### 时间范围含义

- **Now**：问题、负责人和近期结果清楚，正在验证或交付；限制并行数量。
- **Next**：证据支持继续，但方案、依赖或容量尚未完全确认。
- **Later**：值得保留的假设或机会，不构成承诺；定期淘汰长期无新增证据项。

## 8. 容量和投资组合检查

路线图在发布前检查：

- 是否覆盖增长、留存、可靠性／质量、技术健康和必要合规；比例由战略决定，不套固定百分比。
- 是否为发现工作、缺陷、运营和不可预期事件留有真实容量。
- 同一关键角色或平台是否成为多项计划的隐形单点依赖。
- 是否存在“每项都是第一优先”的假对齐。
- 取消或推迟了什么，受影响方是否知道。

## 9. 排序会议

会议前分享候选项卡和评分依据；会议中先处理硬门槛，再讨论最大分歧字段；会议后记录：

- 最终顺序及决定者；
- 被否决／推迟项及原因；
- 未解决异议；
- 需要补的证据；
- 复查日期或触发器。

排序结果必须进入决策日志。新证据、战略变化、估算显著变化或风险跨阈值时重排；不要因为有人声音大就随时插队。
