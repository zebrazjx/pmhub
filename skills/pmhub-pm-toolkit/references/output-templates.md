# 输出模板库

只读取并使用当前任务所需模板。删除不适用段落；对需要但缺失的内容写 `[待确认]` 或 `[待验证]`，不要保留空括号、虚构数字或机械输出整库。

## 通用页首

```markdown
# [产物名称]

- 状态：草案／评审中／已决定／已归档
- 产品／范围：
- Owner：
- Driver／Approver：
- 日期／版本：
- 本文支持的决定：
- 决定截止：
- 相关 Evidence IDs：
- 相关 Decision IDs：

## 执行摘要
[当前结论、理由、最大未知、需要读者采取的动作]
```

## 跨阶段共享状态

端到端或长期项目使用；一次性请求只保留与当前决定有关的行。

```markdown
## 证据账本
| Evidence ID | 日期 | 类型 | 来源／人群 | 观察／数据 | 样本与局限 | 支持／反对 | 可信度 | 关联产物 |
|---|---|---|---|---|---|---|---|---|

## 未知项台账
| Unknown ID | 未知／假设 | 若为假影响 | 当前证据 | 补证据动作 | Owner | 截止／触发 | 状态 |
|---|---|---|---|---|---|---|---|

## 决策索引
| Decision ID | 日期 | 决定 | Approver | 关键理由 | 明确取舍 | 复查触发 | 状态 |
|---|---|---|---|---|---|---|---|
```

## 模板 A0：探索级问题—实验说明

用于用户要求“直接写 PRD”，但当前只有方案／高层指令，尚无目标用户证据的情形。它不是开发承诺。

```markdown
# 探索说明｜[暂定方案／问题]

- 状态：需补证据
- 开发承诺：否
- 原始信号：高层指令／客户请求／团队想法／其他
- 当前方案：仅作待检验假设
- 要支持的下一决定：是否值得进入正式 PRD
- 相关 Evidence IDs：
- 相关 Decision ID：

## 暂定问题
[假设] [人群] 在 [情境] 中可能因为 [阻碍] 难以 [进展]。

## 已知与未知
| 类型 | 内容 | 来源／边界 |
|---|---|---|
| 事实／约束 | | |
| 假设／推断 | | |
| 缺失证据 | | |

## 最危险的三个假设
| Unknown ID | 假设 | 若为假影响 | 最小验证 | 判定信号 |
|---|---|---|---|---|

## 低成本验证
- 目标人群与招募：
- 方法与为何合适：
- 需要观察的过去行为／任务：
- 不可由该方法证明：
- 停止／转向条件：

## 正式 PRD 证据门
- 目标用户和情境已有真实证据；
- 问题／替代／后果可以被描述；
- 至少一个用户结果和一个业务结果可观测；
- 关键价值、可行性及合规风险有 Owner 和处理路径；
- 进入开发、继续实验或停止的决定已记录。

## 下一动作
[Owner、期限、完成证据]
```
