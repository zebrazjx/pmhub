# 指标、实验与增长

按需用于指标体系、埋点、看板、实验、上线、采用率、留存和增长。任何指标都必须说明它会改变什么决定。

## 1. 指标契约

在讨论目标值前，先建立可计算定义：

| 字段 | 内容 |
|---|---|
| Metric ID／名称 | 唯一名称，避免同名异义 |
| 决策用途 | 指标变化后谁会做什么 |
| 用户价值连接 | 它为何代表用户获得价值，而非只代表活动量 |
| 事件与实体 | 事件名、用户／账户／任务等分析单位 |
| 公式 | 分子、分母、聚合方式 |
| 人群 | 纳入／排除条件、首日定义、实验资格 |
| 时间 | 时区、窗口、观察周期、成熟延迟 |
| 去重与异常 | 重复事件、机器人、内部账号、退款／取消等 |
| 数据源与质量 | 表／事件、缺失率、延迟、已知偏差 |
| 基线与目标 | 数值、测量期和目标期限；未知则写获取计划 |
| Owner 与频率 | 负责人、刷新频率、告警阈值 |

“提升活跃度”“优化体验”不是指标定义。不要编基线、样本量或目标值。

## 2. 指标架构

### 北极星及输入树

北极星适合统一长期产品价值，不是所有局部功能都需要重新发明一个。候选指标应：

1. 表示用户实际获得的核心价值；
2. 团队可通过产品行为影响；
3. 对长期可持续业务结果有领先关系或明确假设。

从北极星拆到可行动输入：

```text
长期业务结果
└─ 北极星：被用户重复获得的核心价值
   ├─ 获取输入
   ├─ 激活输入
   ├─ 使用深度／频率输入
   └─ 留存／复购输入
```

每条父子关系都是因果假设，标注证据和反例。北极星旁边必须有质量、信任、安全或经济性护栏。

### HEART

当决定聚焦用户体验时，可从 Happiness、Engagement、Adoption、Retention、Task success 中选与目标相关的维度，不必五项全用。按“目标→信号→指标”推导，避免直接抄一套通用看板。

### 漏斗与队列

- 漏斗每一步必须是同一实体在规定窗口内的有序行为；
- 报告绝对量和转化率，分清资格人群与暴露人群；
- 留存使用同一 cohort 定义，注明自然周／滚动日和观察成熟度；
- 分群用于发现异质性，但避免无假设地切片直到出现“显著结果”。

## 3. 指标树与埋点

建立以下追踪：

> 目标 → 用户行为 → 指标 → 事件／属性 → 数据源 → 看板／告警 → 决策 Owner

埋点计划至少包含：事件名、触发时机、主体、必要属性、示例、隐私级别、客户端／服务端、去重键、验收方式。发布前用测试账号跑完主路径和异常路径，核对事件顺序、数值、身份合并和实验分组。

## 4. 实验设计

### 实验卡

1. **决定**：结果将支持扩大、继续、修改还是停止？
2. **假设**：对哪类人，在什么情境，什么改变会通过什么机制影响什么结果？
3. **最危险假设**：价值、可用性、可行性、商业可行性或合规中的哪一项？
4. **方法**：随机实验、可用性测试、原型、假门、Wizard-of-Oz、准实验或数据分析。
5. **实验单位与资格**：用户、账户、会话、地区等；说明纳入规则。
6. **处理与对照**：具体差异，避免同时改变无法拆分的多项因素。
7. **主指标**：只选一个主要决策指标，给出指标契约。
8. **次指标与护栏**：解释机制并监测伤害。
9. **统计计划**：基线、最小可检测效应、显著性水平、功效、方差／比例、样本量和运行时长。
10. **偏差与干扰**：新奇效应、网络效应、学习／残留、季节、并发实验、选择偏差。
11. **停止规则**：预定样本／时间、严重护栏恶化、技术异常；不要看到好结果就提前停止。
12. **分析和决定规则**：实验前写清各种结果对应的动作，包括无结论。

若缺少样本量计算输入，列出所需输入和计算方法，不凭经验虚构人数。低流量产品可用更大效应门槛、延长时间、聚合到更稳定单位，或选择能回答当前未知的定性／准实验方法。

### 方法与未知匹配

| 未知 | 低成本首选 | 升级方法 |
|---|---|---|
| 用户是否理解／能完成 | 原型＋任务观察 | 灰度行为数据 |
| 用户是否愿意开始 | 假门／明确 CTA | 受控可用版本 |
| 是否持续获得价值 | 人工服务／试点 | cohort 留存／随机实验 |
| 技术是否可行 | 技术尖峰、离线评测 | 受控流量和压力测试 |
| 是否改善业务结果 | 建模／历史准实验 | 随机实验或可信对照 |

## 5. 实验分析

先做数据质量和 Sample Ratio Mismatch 检查，再读效果：

- 实际样本、暴露、缺失和异常是否符合计划；
- 主指标的绝对差、相对差、不确定区间和实际业务意义；
- 护栏是否跨越预设阈值；
- 预注册分群和探索性分群分开标注；
- 结果是支持、反对还是仍不确定，不能把“未显著”直接写成“没有影响”；
- 记录推广限制、机制解释、后续动作和决策日志。

## 6. 上线分级

根据用户影响、可逆性、数据敏感度、技术复杂度和品牌／合规风险选择发布方式：

- **内部／受控测试**：验证主流程和运营能力；
- **小流量灰度**：验证真实环境、监测护栏；
- **分群发布**：先覆盖最合适或最低风险人群；
- **全量发布**：前置证据和回滚能力充分；
- **强制迁移／下线**：需要迁移、通知、支持和例外处理计划。

每个阶段定义：资格人群、流量／名单、持续时间、成功条件、停止条件、扩大批准人、回滚步骤和沟通对象。

## 7. 上线与 GTM 协同

产品上线和市场发布不一定同一天。计划至少覆盖：

| 工作流 | 关键问题 |
|---|---|
| 产品 | 价值主张、目标人群、可用范围、已知限制 |
| 工程／数据 | 稳定性、迁移、监测、回滚、指标成熟时间 |
| 市场／增长 | 定位、渠道、内容、CTA、归因和预算 |
| 销售／成功 | 合格线索、演示、异议、定价、现有客户影响 |
| 支持／运营 | 帮助文档、工单路由、SLA、人工补偿流程 |
| 法务／安全 | 条款、隐私、安全、地区或人群限制 |

发布前明确一个消息真源：能做什么、不能做什么、适合谁、如何获得、出问题去哪里。

## 8. 采用与增长诊断

不要从“多做拉新”开始。先定位漏点：

1. **获取**：目标人群是否到达，渠道承诺是否准确；
2. **激活**：是否在合理时间内首次获得核心价值；
3. **采用**：目标功能在人群和关键任务中是否被正确使用；
4. **留存**：价值是否重复发生，停止使用前的行为是什么；
5. **变现／扩张**：价值是否支持付费、续费、席位／用量增长；
6. **推荐／循环**：产品使用是否自然产生可传播、协作或邀请输出。

每个增长提案写成闭环：触发→用户动作→产生价值／输出→触达下一用户或促使回访→转化→再次触发。估算每步转化、周期时间和成本；若循环需要持续买量才能运转，则把它称为渠道漏斗而非产品增长循环。

## 9. 上线后节奏

按风险调整而非固定套天数：

- **立即／早期**：稳定性、错误、安全、支持量和严重护栏；
- **达到行为成熟窗后**：激活、采用、任务成功和分群差异；
- **达到留存／商业成熟窗后**：留存、扩张、成本和长期护栏；
- **每次检查**：决定扩大、维持、修复、回滚或停止，并更新决策日志。

发布不是完成。只有达到预定观察窗并作出后续决定，才关闭该次产品赌注。
