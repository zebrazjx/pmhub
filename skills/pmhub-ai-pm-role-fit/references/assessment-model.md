# 评分、区间与置信度模型

## 1. 模型目的

对同一个人内部比较九类方向，同时保留四种不同问题：

- `A / affinity`：我愿意长期反复做这种真实工作吗？
- `R / readiness`：我现在能否用行为证据证明关键能力？
- `C / compatibility`：这种工作情境与我的现实约束、反馈周期和协作对象兼容吗？
- `L / learning`：我愿意且能够在目标时间内补关键缺口吗？

不要把四项合成唯一的「适合分」后隐藏原始信息。

## 2. 0—4 行为锚点

每项可以是单值，也可以是 `[下界, 上界]`。未知用 `[0,4]` 或根据已知信息收窄，绝不能填 0。

### Affinity

| 分值 | 锚点 |
|---:|---|
| 0 | 明确反感该角色的核心日常或最终责任，并有持续反例 |
| 1 | 题材有兴趣，但真实任务多为消耗；或只喜欢光鲜部分 |
| 2 | 对核心日常有明确的喜恶混合，或不同任务证据相互矛盾 |
| 3 | 多道匿名任务题一致偏好，能接受主要压力源 |
| 4 | 长期主动选择并反复投入相似任务，即使没有头衔或外部奖励 |

### Readiness

| 分值 | 锚点 |
|---:|---|
| 0 | 明确没有关键能力或经历 |
| 1 | 学习、观察或协助过，无法独立交付 |
| 2 | 课程、练习、社团或个人项目中独立完成局部，有可检查产物 |
| 3 | 真实场景端到端负责，有结果、个人贡献和一次关键取舍 |
| 4 | 在多个场景重复取得结果，能解释方法、边界、失败和迁移条件 |

Readiness 必须用角色源卡的关键任务校准。只在前 3 名中读取对应 32 项；不要把 32 项逐项问用户。技术名词自评、岗位名称和公司品牌不能代替证据。

若要参考原卡模块，技术关键词少于 3／5，或个人项目少于 2／4，应标记「硬证据不足」；原卡总分不能抵消这两项缺口。该规则影响准备度解释，不影响长期兴趣。

### Compatibility

| 分值 | 锚点 |
|---:|---|
| 0 | 存在明确不可协商、且该岗位高频必需的条件冲突 |
| 1 | 多个明显冲突，除非岗位形态特殊或条件改变 |
| 2 | 对已知工作情境喜恶混合，或存在可协商但尚未解决的摩擦 |
| 3 | 主要协作对象、节奏、压力和环境均可接受 |
| 4 | 过去长期处于相似情境仍可持续，并主动选择这种环境 |

硬冲突还必须写进 `hard_conflicts`；不能只用低分淡化。

### Learning

| 分值 | 锚点 |
|---:|---|
| 0 | 明确不愿补该角色的关键门槛 |
| 1 | 口头愿意，但投入极少、时间不现实或无交付承诺 |
| 2 | 有有限时间与模糊计划，能做小范围验证 |
| 3 | 每周有稳定投入，愿做针对性项目并接受邻近切入 |
| 4 | 已开始行动，有里程碑、反馈者、产物与可验证截止日期 |

## 3. 证据质量与覆盖

`evidence_quality` 为 0—1，仅用于置信度，不再重复乘进 Readiness：

- 0.00：没有相关信息；
- 0.50：只有针对真实任务的形容词式自评，尚无行为例子；
- 0.75：有具体动作／产物，但缺结果或个人贡献边界；
- 1.00：有情境、个人动作、结果、取舍和复盘，可被作品或他人追问。

`coverage` 是该角色关键判断中已获得有效信息的比例。`consistency` 是不同题型是否指向相近结论：完全矛盾约 0.25，混合 0.50，多数一致 0.75，高度一致 1.00。不要为了提高一致性删除反面证据。

MBTI、星座等标签本身不是有效证据：仅有这些标签时，不得提高 `evidence_quality`、`coverage` 或 `consistency`。只有用户另行讲出的具体任务偏好或行为经历，才能按其自身质量编码；编码依据是经历，不是标签。

## 4. 双榜公式

所有原始项先从 0—4 归一为 0—100。默认：

```text
当前可切入 = 35% A + 45% R + 20% C
值得发展   = 50% A + 15% R + 20% C + 15% L
```

含义：当前榜更看重已经能证明的能力；发展榜更看重真实兴趣，并允许学习意愿影响方向。市场岗位量、MBTI、星座、学校与公司品牌权重全部为 0。

只显示整数和区间，不显示小数伪精确。首版权重是透明的产品决策规则，不得宣称为已通过心理测量验证的量表。

## 5. 区间、排名和硬冲突

- 对每项上下界分别计算，得到岗位分数区间。
- 内部计算、排序和阈值判断使用未四舍五入值；只在展示时取整。
- 默认按区间中点形成候选顺序，报告同时显示区间；重叠候选属于同一不确定候选组，不用名称或隐藏小数强造先后。
- 第一名下界不高于第二名上界时（含端点相接），说明区间重叠。
- 第一、二名中点差小于 8 分，或区间重叠时，触发自适应追问。
- 硬冲突岗位仍显示原始分和潜在价值，但标记「条件冲突」；不得静默删除，也不得伪装成低兴趣。
- 如果追加 4 题后仍重叠，输出并列候选和两个现实检验任务。

## 6. 置信度

对榜单 Top 3 计算：

```text
置信度 = 30% 关键维度覆盖
       + 30% 行为证据质量
       + 20% 多题型一致性
       + 20% 第一／二名分离度
```

分离度由未四舍五入的中点差和区间重叠决定。先计算 0—1 的「稳定性指数」，再结合证据门槛给标签：

- 高：指数 ≥ 0.75，且第一名 `evidence_quality = 1.00`、至少有一条完整行为证据、Top 2 区间不重叠；
- 中：指数 ≥ 0.55，但未满足全部高置信门槛；
- 低：指数 < 0.55。

因此可能出现「中（稳定性指数 0.88；缺完整行为证据）」；这不是数值区间冲突，而是被证据门槛降级。输出必须同时说明降级原因。

高置信度只表示「基于当前输入，排序较稳定」，不是预测工作表现或 Offer。

## 7. JSON 输入格式

评分脚本需要九个固定角色。单值和 `[下界, 上界]` 均可：

```json
{
  "candidate": "示例用户",
  "consistency": 0.75,
  "followup_count": 0,
  "roles": {
    "application": {
      "affinity": [3, 4],
      "readiness": [2, 3],
      "compatibility": 4,
      "learning": [3, 4],
      "coverage": 0.8,
      "evidence_quality": 0.75,
      "technical_evidence_count": 3,
      "personal_project_count": 2,
      "hard_conflicts": [],
      "evidence": ["主动访谈 6 名用户并迭代原型"],
      "tensions": ["尚无线上留存数据"],
      "unknowns": ["是否能长期接受高频 Bad Case 分析"]
    },
    "agent": {},
    "model_strategy": {},
    "solution_delivery": {},
    "growth_commercial": {},
    "edge_hardware": {},
    "platform_infra": {},
    "data_evaluation": {},
    "safety_governance": {}
  }
}
```

`technical_evidence_count` 为原卡技术模块已被具体证据支持的条数（0—5），`personal_project_count` 为个人项目模块证据条数（0—4）；未知时省略或写 `null`，不得猜测。任一已知值低于 3／5 或 2／4，脚本必须把当前切入状态标为「硬证据不足」，即使 Readiness 的综合判断较高。两项未知时写「原卡门槛未核验」，不能宣称已满足直接投递证据。

`followup_count` 记录本次诊断已经追加的判别题数（0—4）。未满 4 且 Top 2 仍不稳定时可继续追问；达到 4 后必须停止问卷，把重叠者作为并列候选并给现实检验。

每个角色对象只允许上述四个维度、`coverage`、`evidence_quality`、两个原卡证据计数以及 `hard_conflicts`、`evidence`、`tensions`、`unknowns`。拼写错误或其他未知字段必须报错，不得静默退化为未知。若 `hard_conflicts` 非空但 Compatibility 明显高于 0，脚本应给一致性警告，要求编码者复核；硬冲突通常应对应 `C = 0`。

空对象会被视为全部未知并形成宽区间，适合中途暂定报告；不能把它解释为低分。完整报告前应尽量收窄九类的 Affinity 和 Compatibility，并重点收窄候选 Top 3 的 Readiness。所有真正未知的维度都必须保留为区间；0—4 锚点中的 2 只表示已观察到的混合证据，不得用作「不知道」的默认值。

## 8. 运行与解释

将 JSON 保存到临时文件后，从 Skill 目录运行：

```bash
python3 scripts/score_assessment.py --input <assessment.json> --format markdown
```

脚本输出双榜、区间、冲突、置信度和是否需要追问。模型负责把结果连接到用户证据和岗位真实日常，不能新增脚本中不存在的分数。

## 9. 专业方法边界

- O*NET Content Model 将职业信息区分为工作者特征、技能／知识、经验要求、工作活动、工作情境和市场信息；本模型因此不把人格、能力、经历与岗位市场混成一项：https://www.onetcenter.org/content.html
- 美国 OPM 的结构化访谈指南要求先做岗位分析，问题来自真实职责，并用一致评分锚点；本题库同时使用行为题和情境题：https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/guide.pdf
- OPM 对工作样例的说明强调让受测者完成与岗位相同或高度相似的任务；因此报告必须给现实检验任务：https://www.opm.gov/policy-data-oversight/assessment-and-selection/other-assessment-methods/work-samples-and-simulations/
- 美国国家研究委员会曾指出，没有充分、设计良好的研究支持将 MBTI 用于职业咨询；因此 MBTI 只作叙事、权重为 0：https://www.nationalacademies.org/read/1580/chapter/8
- 双盲占星研究检验了出生星盘描述人格的主张；星座不进入岗位因果评分：https://www.nature.com/articles/318419a0

## 10. 上线前后的校准要求

V1 只能称「基于岗位画像与行为证据的探索工具」。若要声称测评有效，至少需要：

1. 让九类在岗从业者复核任务、压力源和证据锚点；
2. 用留出用户盲测题目是否能区分能力强但倦怠、兴趣高但零经验、通才并列、约束冲突等情况；
3. 检查同一人短期重测稳定性与改答案后的敏感性；
4. 跟踪现实检验、投递和入职后的结果，但不把短期 Offer 当唯一效标；
5. 审计不同群体是否因无关身份产生系统性差异；
6. 权重或岗位资料变化时版本化并重跑回归样本。
