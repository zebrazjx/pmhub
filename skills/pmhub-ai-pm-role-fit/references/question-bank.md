# 统一访谈题库

## 使用方式

标准版是 13 道核心题 + 1 道可选自我叙事题，必要时追加 0—4 道判别题。通常 14—16 题、10—15 分钟，绝不超过 18 题。题号稳定；已经从简历或对话中获得的答案要先预填并让用户纠正，不得重复问。

标记为「必答」的 7 题构成快速版：Q1、Q3、Q4、Q5、Q10、Q11、Q13。快速版只能输出暂定结果。

每轮最多问 4 题。先告诉用户可用字母、排序或短句回答，真实反感和失败经历与优势同样有价值。

## 第一轮：目标、经历、约束

### Q1｜决策目标（必答，不直接计分）

> 你现在最想解决什么决策：第一次进入 AI 产品、选实习／校招方向、从传统产品转型、在职换方向，还是验证当前岗位？希望多久内采取行动？

记录招聘类型、时间线，以及报告应优先看「当前可切入」还是「值得发展」。

### Q2｜经历基线

> 过去两年，你做过哪些工作、项目、课程、社团或个人作品？每项分别服务谁、你具体负责什么、做到哪一步、结果如何？没有正式工作经历也完全可以写其他实践。

优先提取九类可迁移背景，不因品牌或头衔加分：

- C 端／SaaS／工具／用户体验；
- 工作流／自动化／开发者工具；
- 算法／数据／搜索推荐／实验；
- B 端咨询／售前／实施／客户成功；
- 增长／广告／电商／商业化／运营；
- 硬件／汽车／机器人／IoT／嵌入式；
- 云／数据平台／API／基础设施；
- 测试／质量／标注／模型评测；
- 安全／风控／内容治理／隐私合规／高风险行业。

### Q3｜现实硬约束（必答）

> 以下工作条件中，哪些是你明确不能接受、勉强可接受或反而喜欢的：高频出差／客户现场、客户冲突与范围谈判、销售或收入目标、较长研发反馈周期、值班与生产故障、实验室／产线／供应商、高监管与审计、大量样本复核、较深技术学习、主要服务内部开发者？还有城市、招聘类型或时间上的硬限制吗？

只有用户明确为「不能接受」，且岗位画像确认为高频真实条件时，才登记硬冲突。不要从家庭、性别、年龄或地域身份推断约束。

## 第二轮：真实工作偏好

### Q4｜任务能量排序（必答）

> 如果未来一年要反复做下面这些事，请选「最想长期做的 2 项」和「最消耗的 2 项」，并各说一句原因。

| 代码 | 真实日常任务 |
|---|---|
| A | 访谈用户、看会话与行为，做原型并改体验 |
| B | 拆多步任务、读 Trace、处理工具失败、重试与权限 |
| C | 看模型／策略版本、原始样本和实验结果，决定下一版优化什么 |
| D | 进入客户流程，做 POC、集成、部署、验收和标准化 |
| E | 拆激活、留存、定价、渠道、收入和单位经济 |
| F | 在精度、延迟、功耗、BOM、量产与现场可靠性间取舍 |
| G | 做 API／SDK、模型路由、配额、SLA、版本兼容和开发者体验 |
| H | 抽样、定标签标准、处理标注争议、评测与 Bad Case 回流 |
| I | 做威胁建模、红队、权限控制、审计和事故响应 |

映射：A—应用，B—Agent，C—模型策略，D—解决方案，E—商业化，F—端侧硬件，G—平台，H—数据评测，I—安全治理。选择只是偏好信号，原因与反感内容比字母更重要。

### Q5｜匿名项目选择（必答）

> 假设薪资、公司名和职级相同，从下面项目中选「最想负责的 2 个」和「最不想负责的 2 个」，并说你第一周会先看什么证据。

| 代码 | 项目现场 |
|---|---|
| A | 一款 AI 知识助手注册很多但任务完成和周留存下降，需要从用户任务、交互、质量和成本中找根因 |
| B | 一个报销 Agent 能调用多个系统，但会重复提交、权限报错且中途状态丢失，需要提高连续成功率 |
| C | 候选模型平均分提升，但核心业务切片退化且推理更贵，需要决定训练、灰度或回滚 |
| D | 企业客户认可 Demo，却卡在 SSO、数据隔离、私有化、运维和验收，销售又承诺了额外需求 |
| E | AI 创作产品获客快但留存、付费和毛利差，需要重定义激活、套餐、路由与 GTM |
| F | 端侧视觉功能精度高但发热、续航和 BOM 超标，样机可用而量产风险很大 |
| G | 多个团队各自接模型，接口、日志、权限和成本失控，需要建设共用模型网关但避免伪中台 |
| H | LLM Judge 给高分，但双人人评争议大、评测集重复且线上 Bad Case 没回流 |
| I | Agent 最终回复看似安全，却在过程中读取了未授权数据，需要定位攻击路径并决定是否停发 |

映射与 Q4 相同。Q4 与 Q5 相反时不要平均掉，先记录矛盾：用户可能喜欢题材，却不喜欢真实工作。

### Q6｜产品阶段与反馈周期

> 请给下面工作方式排序，并说明你能长期接受的反馈周期：① 从模糊问题找到 0→1；② 在成熟产品中连续实验和优化；③ 建长期平台与规模治理；④ 进客户现场交付并标准化；⑤ 围绕硬件／模型做数周到数月验证。

这是情境兼容信号，不是直接岗位答案。偏好 ③ 往往支持平台、Agent、数据或安全；④ 支持解决方案；⑤ 支持模型与端侧；①② 可同时支持多个方向。

### Q7｜结果责任排序

> 真正需要你背结果时，最愿意负责哪 2 项、最不愿意负责哪 1 项：用户任务成功与留存；多步任务可靠性；模型／策略效果；客户验收与 ROI；增长／收入／毛利；设备性能与量产；平台 SLA 与复用；数据／评测质量；安全事件与风险？

九项依次映射九类角色。此题权重高于「我喜欢某岗位名称」。

## 第三轮：人群、判断方式与能力证据

### Q8｜长期协作对象

> 最愿意和最不愿意长期服务或协作的对象分别是谁，为什么：普通终端用户、企业一线与决策者、销售／市场／运营、开发者与内部团队、算法／数据团队、供应商／产线／现场、法务／安全／监管／领域专家？

把「善于沟通」和「愿意长期面对谁」分开。解决方案高分通常需要企业客户兼容；平台需要开发者／内部用户；模型与评测需要算法／数据；端侧需要供应链／现场；安全需要安全、法务、监管或专家协作。

### Q9｜模糊情境题

> 老板只说「这个方向最近很火，两周给我一个是否做的建议」，业务、用户、算法和销售意见互相冲突。你的第一周会先做哪 3 个动作？会主动放弃什么？什么证据会让你改结论？请按你真实会做的方式回答。

没有标准答案。根据用户自然优先的证据编码：用户与任务、Trace 与系统、模型与实验、客户流程与 ROI、漏斗与商业、物理约束、平台共性、样本与标准、风险与责任。只说「先调研」不够时追问调研对象和决策阈值。

### Q10｜能力证据矩阵（必答）

> 请按 0—4 给每类能力标级，并给最高的 1—2 项各写一条证据：0 没接触；1 学习／协助；2 独立完成局部或个人项目；3 真实项目端到端负责且有结果；4 多个场景重复拿到结果并能解释关键取舍。拿不准写「未知」，不要谦虚或虚高。

| 能力组 | 包含内容 |
|---|---|
| 用户与体验 | 访谈、任务拆解、原型、可用性、采用／留存 |
| AI 与技术系统 | LLM／RAG／Agent、API、日志、系统边界、原型排障 |
| 数据、实验与评测 | SQL／分析、A/B、样本、指标、Bad Case、版本比较 |
| 企业、行业与商业 | 企业流程、行业知识、客户、ROI、定价、GTM、单位经济 |
| 复杂交付与影响力 | 跨团队、范围取舍、上线、验收、冲突、回滚／复盘 |
| 专项资产（选填） | 平台基础设施、硬件系统、安全治理、模型算法、标注质检、内容多模态中最强项 |

不能把同一段经历在多个能力组重复计成多次独立证据；可以说明一条经历同时覆盖哪些能力。

评分前，从 Q2、Q10、Q11 已给出的事实中，按前 3 名对应的源卡核对：技术模块 5 项中有几项得到具体证据支持，个人项目模块 4 项中有几项得到支持，分别写入 `technical_evidence_count` 与 `personal_project_count`。只有明确提到可检查产物、动作或结果才计数；没谈到就留 `null`，不能凭综合能力等级猜数。若这个门槛会改变「当前可切入」结论，可把相关 5＋4 项压缩成一道勾选式核验题，只核验候选角色，不让用户重做整张 32 项卡。

## 第四轮：行为、反证、可行性

### Q11｜最强行为证据（必答）

> 讲一件最能代表你产品判断的事：当时情境和目标是什么；你个人做了什么关键动作与取舍；结果和证据是什么；哪部分不是你做的；若重来会改什么？

用行为锚点评分，不因故事长、头衔高或结果漂亮自动加分。缺少个人贡献或结果时只问一次具体追问。

### Q12｜可持续性与反面证据

> 哪类工作你能做得不错，但长期会被耗尽？哪次经历让你确认不想再反复做某类事情？如果没有，请说一个你最担心的真实岗位压力源。

这是防止「会做 = 适合」的关键题。真实反例可降低 `affinity` 或 `compatibility`，不直接抹去 `readiness`。

### Q13｜转型可行性（必答）

> 未来 6 个月每周能稳定投入多少时间？最愿意补哪 2 类能力、最不愿意补哪 1 类？愿意先做邻近岗位、7—14 天现实检验或一个可运行项目吗？请给出你实际能完成的最小承诺。

`learning` 依据具体时间、愿补能力与可交付承诺评分；「我愿意努力」但无可执行投入只记较宽区间。

### Q14｜可选自我叙事，不计分

> 如果你愿意，可以提供 MBTI、星座或他人常用来形容你的词；请同时说两条被具体工作经历支持的描述，以及一条明显不符合你的描述。跳过完全不影响结果。

任何 MBTI／星座字段进入分数、置信度、证据覆盖或一致性都属于实现错误。可将用户另行给出的、有行为支持的描述作为待验证假设，用普通语言写入画像；这条经历按自身质量判断，不以标签解释岗位因果。

## 自适应追问

只为解决具体不确定性追加，最多 4 题：

| 高概率并列 | 最有效的判别题 |
|---|---|
| 应用 vs Agent | 同一 AI 助手，你愿意连续一周访谈／改交互与留存，还是读 Trace／修工具、状态、权限？为什么？ |
| Agent vs 平台 | 更想拥有一个 Agent 的端到端成功，还是让十个团队稳定接入共用能力？当两者冲突时选谁？ |
| 模型策略 vs 数据评测 | 更想决定模型下一版强化什么与是否发布，还是建立让这个决定可信的数据、标准和评测体系？ |
| 解决方案 vs 商业化 | 更愿为三个复杂客户完成验收并产品化，还是围绕一类用户做规模获客、定价、留存和毛利？ |
| Agent vs 安全治理 | 当任务成功和风险护栏冲突，你更愿意承担哪一种最终责任与停止权？ |
| 应用 vs 商业化 | 用户体验提升但收入不涨时，你更自然继续深挖任务价值，还是重构人群、定价、渠道和商业模型？ |
| 端侧 vs 软件方向 | 是否愿意为了一个指标在实验室、供应商和现场迭代数周，而不是当天上线软件实验？举例。 |
| 其他组合 | 假设薪资、头衔、公司和发展空间相同，描述两类岗位真实一周，强制二选一，并问什么证据会改变选择。 |

还可使用：关键缺口的 10 分钟工作样例；请用户补一个与自评矛盾的具体经历；确认某个硬约束是否真的不可协商。

## 提问纪律

- 不在提问时透露哪个选项「更高级」或当前领先者，避免迎合答案。
- 不赞美社会期待型回答；用中性确认继续。
- 不问与职业探索无关的敏感身份。
- 达到题目上限、用户要求停止或结论已稳定时，立即转入报告。
