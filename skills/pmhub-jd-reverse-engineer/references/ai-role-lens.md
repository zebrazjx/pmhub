# AI 岗位透镜

仅在 JD 含 AI 信号或用户要求判断“真 AI／蹭 AI”时使用。

## 先判 AI 在责任链中的位置

不要二元化为“真／假”。使用三类结论：

| 分类 | 主要特征 | 求职含义 |
|---|---|---|
| AI 核心岗 | AI 系统质量直接决定用户任务与业务结果，岗位对 AI 方案、效果或交付负责 | 需要模型边界、系统方案、评测与失败处理证据 |
| AI 增强岗 | 核心职责仍是某类业务产品，但 AI 是明确产品模块或重要提效手段 | 既要业务主能力，也要证明能把 AI 嵌入真实流程 |
| AI 邻近／标签弱 | AI 只出现在标题、趋势关注或通用工具提效中，缺少具体用户、对象、责任与指标 | 可以是好业务岗，但不能自动积累核心 AI 产品证据 |

结论必须给置信度。信息不全时写“当前更像……，需验证”，不要直接贴“蹭 AI”标签。

## 六项真实性检查

1. **价值位置**：AI 是否决定核心价值，而非边角功能？
2. **工作对象**：是否出现具体对象，如模型、数据、Prompt、RAG、Agent、Tools、多模态或评测？
3. **效果责任**：岗位是否要定义好坏、分析 Bad Case、优化效果并对指标负责？
4. **资源链路**：是否有算法、工程、数据团队，或清晰的外部技术方案与责任边界？
5. **落地入口**：是否有真实用户、数据、业务流程、接口／设备和部署路径？
6. **业务闭环**：是否能说明效率、增长、收入、质量、成本或风险会怎样改变？

每项使用“有明确证据／有弱信号／无信息／存在反证”。没有信息不等于反证。

## 判断岗位形态

岗位名称不是可靠分类。优先看主责任链：

| 形态 | 反复负责的对象 | 典型证据重点 |
|---|---|---|
| AI 应用 | 具体用户任务、AI 原生交互、留存与价值闭环 | 用户研究、原型、模型边界、端到端指标 |
| Agent | 多步骤任务、工具、状态、权限、失败恢复与人工接管 | 工作流、工具边界、Trace、任务评测、安全 |
| 平台／开发者工具 | API、组件、工作流、发布、观测、生态与治理 | 架构理解、开发者体验、可靠性、采用率 |
| 解决方案／交付 | 客户问题、方案配置、集成、实施、验收与复制 | 行业流程、交付、范围控制、ROI 与复用 |
| AIGC／多模态 | 内容生产链、可控性、一致性、编辑、审核与分发 | 质量标准、多模态链路、版权、安全、成本 |
| 行业 AI | 专业任务、行业数据、责任边界与合规 | 行业知识、专业评测、数据治理、人工责任 |

这些维度可以重叠。先选“主要结果责任”，再补产品形态和行业场景，避免看到 Agent 一词就把岗位判成平台岗。

## 技术词要翻译成决策

对每个技术词追问四件事：

1. 它解决哪段用户任务？
2. 为什么不用更简单的规则、搜索、工作流或人工方案？
3. 岗位需要做到“理解、选型、设计、评测、集成、编码、运维”的哪一级？
4. 质量、延迟、成本、权限、安全和维护之间如何取舍？

常见翻译：

| 技术信号 | 不能只背的定义 | 产品责任可能包括 |
|---|---|---|
| LLM／Prompt | 模型会生成文本 | 任务边界、结构化输出、版本、稳定性与成本 |
| RAG／知识库 | 向量检索加生成 | 数据更新、分块、召回、重排、引用、权限与评测 |
| Agent／Tool Calling | 模型会调 API | 任务分解、工具选择、参数、状态、副作用、恢复与接管 |
| 多模态 | 能处理图像／语音／视频 | 输入质量、同步、可控性、一致性、延迟、版权与审核 |
| API／平台 | 提供接口 | Schema、鉴权、限流、错误处理、观测、文档与开发者采用 |
| 评测 | 跑一个分数 | 测试集、Rubric、失败分类、基线、回归与线上指标 |

只分析 JD 中出现或由任务链路强烈要求的技术；其余不要为了显得专业而堆上去。

## 常见指标与风险是假设，不是公司事实

- 用户结果：任务完成率、一次解决率、采用率、留存、人工接管、满意度；
- AI 质量：正确性、忠实性、召回、引用支持、工具成功率、稳定性；
- 系统护栏：P95 延迟、每成功任务成本、可用性、错误率；
- 风险：幻觉、越权、隐私、提示注入、错误副作用、内容安全、版权、合规。

若 JD 未写，标为 `[合理推断]`，并给出应向面试官确认的口径。
